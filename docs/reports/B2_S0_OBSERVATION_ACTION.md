# B2-S0：Observation 与 Action 契约（SIM_ONLY）

日期：2026-11-13（KST）；[配置](../../configs/b2_s0_circle_sim_only.json)，[实现](../../src/robot_rl_sim2real/circle_rl.py)。以下为仿真实验接口，未对齐真实 SDK。

## Observation：31 维

顺序固定为 `joint1…joint6`，实际 PhysX 名称经名称映射核验；`q` 和 `dq` 来自当前机器人反馈张量，`p_ee` 用同一 `q` 做独立 CPU URDF FK，`p_d`、`v_d` 与之均在 base_link 坐标系。各分量按下表直接相除，不额外裁剪到 `[-1,1]`。

| 元素 | 维数 | 物理单位 | 归一化 |
|---|---:|---|---|
| `q−q_home` | 6 | rad | `/0.35 rad` |
| `dq` | 6 | rad/s | `/0.5 rad/s` |
| `p_d−p_ee` | 3 | m | `/0.01 m` |
| `v_d` | 3 | m/s | `/(0.01×2π/8) m/s` |
| 上一实际应用的归一化动作 `a_prev` | 6 | 无 | 已限幅 |
| 上一位置目标与实测位置之差 `q_target_prev−q` | 6 | rad | `/0.012 rad` |
| 自 reset 起 episode 时间 `t` | 1 | s | `/10.5 s` |

用户提出的24维候选增补目标差6维和时间1维：动作累加到上一位置目标时，目标是控制器内部状态。如果不提供这个已知命令差，Actor 看不到影响下一次控制的状态。恒速圆起点和终点的位置及速度相同，但随后分别进入恒速和减速，故还需时间区分。实际 q/dq 和 FK 依然是观测主体；这些新增量来自先前命令与参考时钟，不是仿真特权量。真实接口能否获得和对齐 q/dq、目标时序及速度估计仍 UNKNOWN。

## Action：6 维目标增量

网络输出 `u∈[-1,1]^6`。不满足维数的批次被拒绝；包含非有限数或超范围的输入被标记为异常并终止相应环境。异常控制步使用限幅后的实测 q 作为临时目标，若反馈非有限则使用上次有效 q，不把异常值写入 PhysX。该终止在最多四个物理子步后返回。正常输入逐轴按下列公式处理：

```text
b_t = a_prev + clip(u_t - a_prev, -0.25, +0.25)
q_target_t = clip(q_target_prev + 0.003 rad × b_t, q_low, q_high)
a_t = (q_target_t - q_target_prev) / 0.003 rad
```

其中 `q_low/high` 取 URDF 位置限位内侧 0.02 rad 与 `q_home±0.35 rad` 的交集；记录的 `a_t` 是位置裁剪后实际应用的增量，并作为下一步动作历史。零动作在动作变化率逐步回到零后保持上一目标；reset 后的首个零动作直接保持初始目标。单步最大位置目标变化 `0.003 rad`，动作变化率最大 `0.25/步`；仿真控制 `60 Hz`，因此最大目标变化率为 `0.18 rad/s`。这些是 SIM_ONLY 诊断数值，不是电机速度、加速度或硬件安全规格。

目标以 60 Hz 更新并在四个物理子步保持；[底层](../../src/robot_rl_sim2real/isaac_circle_env.py#L244)显式设置零速度目标与 PD 力矩，并根据记录的 `controller_mode` 选择是否叠加模型重力前馈。`q_target`、实测 q/dq、原始动作、实际动作及控制力矩均写入本地逐步日志。无特权 Actor 输入不代表 SDK 已能以此频率覆盖指令。
